# Governed account-tariff metadata reads

This source checkpoint adds current-authorized reads of retained ACCOUNT_TARIFF_V1 definitions. It supports BANKING/CURRENT accounts with interest NONE and overdraft NOT_OFFERED. Responses remain NOT_ADMITTED. It does not author, approve or publish definitions, activate financial capabilities, or complete the staff wizard.

## Source dependency requirement

The serving boundary uses shared security APIs from `fireflyframework-jafly` commit `ef2a5e6345be99033e93e3af8c33cd6fdfa7d070`. The previously released `26.10.22` artifacts do not provide the required constructor/projection contract. This is a source-reactor checkpoint; a coordinated new framework release and consumer dependency update are still required. Do not replace a released same-version artifact in a shared Maven repository.

Build the exact shared source and this repository together in an isolated Maven aggregate containing both roots, selecting `:core-common-product-mgmt-sdk -am verify`. This runs the original owner producer and generates the SDK from its actual OpenAPI output. Both packaged SDK resource paths, `openapi.yml` and `api-spec/openapi.yml`, receive those same generated bytes through the declared resource mirror. No generated SDK Java is maintained by hand.

## Trust and configuration

Configure these values from the deployment environment:

| Variable | Meaning |
| --- | --- |
| `PRODUCT_DEFINITION_ISSUER` | Exact trusted JWT issuer |
| `PRODUCT_DEFINITION_AUDIENCE` | Required resource-server audience |
| `PRODUCT_DEFINITION_JWKS_URI` | Trusted issuer's JWKS endpoint |
| `PRODUCT_DEFINITION_POLICY_URL` | Current OPA policy service base URL |
| `PRODUCT_DEFINITION_POLICY_PATH` | Exact OPA decision path |

The JWT must have a current finite expiry, the matching `tenant_id`, and exact scope `product:definitions:read`. Shared signature/issuer/audience validation precedes owner checks. The current policy receives actions `product.definition.root.read`, `product.definition.revision.read`, or `product.definition.publication.read`, with the scoped tenant/root/resource and fixed supported profile. The policy must grant the actual requested resource; a scope alone is insufficient.

New read routes use a dedicated stateless bearer chain. They do not reuse sessions or cache authorization/response outcomes. Existing legacy route security remains its prior behavior and requires its own security review; this checkpoint is not platform-wide security acceptance.

## Database deployment

Apply original migrations with separate migration credentials. V18 requires the pre-provisioned NOLOGIN, non-superuser, non-BYPASSRLS guard role. V19 requires the separately provisioned `firefly_product_definition_serving` role with those same restricted attributes and no private schema/owner access. Review the exact catalogue checks and grants in V18/V19; migrations do not silently create elevated runtime roles.

The application login may inherit the narrow serving role, but must not own relations, assume the guard, write native tables/columns, create schema objects, or have effective database CREATE/TEMPORARY rights. Use a dedicated database with reviewed grants; no automatic revocation or broad legacy ACL/RLS change is performed. Context is a short trusted application projection after policy evaluation, not PostgreSQL verification of a JWT or an instantaneous revocation guarantee.

Reads use mapped Spring Data repositories on one ConnectionFactory in a read-only repeatable-read transaction. Current policy runs before and after completed SQL, without peer calls in a retained connection. Native DB-time checks bound context to current finite admission. Missing or unavailable authority fails closed. Responses exclude private cost/editor/review fields and use `Cache-Control: no-store`.

## Routes and limits

* `GET /api/v1/tenants/{tenantId}/product-definitions/{rootId}`
* `GET /api/v1/tenants/{tenantId}/product-definitions/{rootId}/revisions/{revisionId}`
* `GET /api/v1/tenants/{tenantId}/product-definitions/{rootId}/publications/{publicationId}`

Publication reads additionally require stored product-version identity to belong to the root's product. No new legacy `product_version` grants are provided. Missing, inconsistent, or unavailable version evidence returns a sanitized unavailable result; positive publication serving remains unqualified pending a real lifecycle-supported scoped capability and coherent owner-created publication. Do not disable managed guards or manufacture publication rows to make deployment appear ready.

The generated SDK exposes `root`, `revision`, and `publication`. An optional read idempotency header does not bypass current checks. Root/revision metadata behavior has been exercised with a controlled signed issuer and real OPA, distinct from live staff authority or downstream financial acceptance.
